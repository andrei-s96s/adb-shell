# ADB Shell Desktop — план переноса на Electron

Стек: **Electron** (выбран за надёжность/обкатанность — VS Code, Slack,
Discord, Figma Desktop; не самый современный из рассмотренных, но самый
проверенный в продакшене). Цель — не просто "порт под Windows", а со
временем единая кроссплатформенная замена macOS-версии на Swift (Electron
одинаково собирается под Windows, macOS и Linux из одной кодовой базы).

Живёт в этом же репозитории, в `desktop/` — не трогает `Sources/`,
`Package.swift`, Swift-тесты и CI. Полностью независимый Node/TypeScript
проект.

## Статус

- [x] Фаза 0 — каркас проекта, тулинг
- [x] Фаза 1 — реальный Electron-процесс (main/preload/renderer), список
      устройств в окне, подключение по IP
- [x] Фаза 2 — вкладка "Приложения": список (system/user), детали,
      runtime-разрешения (выдать/забрать), force-stop/очистка
      данных/enable-disable/удаление. **Не перенесено**: F-Droid проверка
      обновлений, экспорт/импорт наборов приложений, снапшот устройства —
      это отдельный, более сложный кусок Swift-версии, осознанно отложен
- [x] Фаза 3 (частично) — Shell-раннер (без истории/избранного/broadcast) и
      файловый браузер (навигация, mkdir, удаление). **Не перенесено**:
      push/pull через нативные диалоги выбора файла, макросы (движок
      переменных + JSON импорт/экспорт) — не начаты
- [x] Фаза 4 — Wi-Fi ADB, проброс портов (forward/reverse), свойства
      устройства с поиском — всё в одной вкладке "Инструменты"
- [x] Фаза 5 (частично) — вкладка "Мониторинг": CPU/RAM/батарея (опрос раз
      в 2с, как в Swift-версии), спарклайн CPU за последние 30 отсчётов,
      список процессов с kill. Вкладка "Logcat": живой стрим (долгоживущий
      `adb logcat` процесс в main, строки уходят в renderer через IPC-
      событие, а не invoke), фильтр по тексту/тегу/уровню, подсветка по
      уровню, очистка буфера устройства. **Не перенесено**: зеркалирование
      экрана через scrcpy, снапшоты устройства, экспорт истории
      мониторинга в CSV, просмотр ANR/tombstone — зеркалирование
      требует вшивать/спавнить scrcpy и управлять его окном, снапшоты —
      писать zip-архивы (в Node нет built-in зип-райтера) — оба
      достаточно самостоятельные куски работы, отложены
- [x] Фаза 6 — упаковка (electron-builder: NSIS для Windows, zip для
      macOS), иконки, `adb.exe` + DLL вшиты в Windows-сборку через
      vendor/win/ + win.extraResources. Самообновление (electron-updater)
      пока не подключено — не начато
- [ ] Фаза 7 — CI на паковку/релиз по тегу (сейчас desktop-build.yml
      собирает, тестирует и паковкует на каждый push, но релизных
      артефактов в GitHub Releases не публикует — только build artifacts
      самого workflow)

Проверено вручную через Chrome DevTools Protocol (не только `node --test`
для чистой логики, но и реальный запуск Electron + проверка живого DOM) —
поймано и исправлено минимум два реальных бага именно так: двойное
исполнение classic-скрипта рендерера и отсутствующие `.js`-расширения в
относительных импортах (TypeScript `moduleResolution: "bundler"` не
добавляет их сама, а нативный ESM в браузере требует явно).

## Почему именно так по фазам

Портируется не код, а **спецификация**: каждый существующий Swift-парсер
(`ADBService.parseDevices`, `GetpropParser`, `PortForwardParser`,
`IpRouteParser`, `ApkBadgingParser`, `DumpsysParser` и т.д.) уже имеет
входные/выходные данные, зафиксированные в Swift-тестах (`Tests/AdbShellTests/`)
— их переносим на TypeScript почти механически, с тем же набором тестовых
кейсов. Это самая низкорисковая часть работы и сделана в первую очередь.

UI-слой переносится экраном за экраном, используя работающее Swift-
приложение и его локализацию (`Localization/ru.lproj`, `en.lproj`) как
эталон поведения и копирайта — не гадаем формулировки заново.

## Технические решения

- **Язык**: TypeScript, компилируется через `tsc` в `dist/` — Electron
  использует собственный встроенный Node/V8, полагаться на нативную
  поддержку TS в системном Node (26+) внутри Electron не стал —
  стандартный и предсказуемый путь.
- **Тесты**: встроенный `node --test` (без Jest/Vitest) — для чистых
  функций парсинга этого достаточно, лишняя зависимость не нужна.
- **UI**: пока простой HTML/CSS/TS без фреймворка — экран небольшой
  (список устройств + shell), фреймворк (React и т.п.) добавим при
  реальном разрастании интерфейса на Фазе 2+, а не заранее.
- **Тема**: цвета/шрифты из `Sources/AdbShell/Design/Theme.swift` (CP.*)
  переносятся как CSS custom properties — визуальная преемственность.
- **Бинарники**: `adb.exe`/`scrcpy`/`aapt2` под Windows — те же источники,
  что `build_app.sh` использует под macOS, просто Windows-сборки; скрипт
  загрузки будет добавлен на Фазе 6 вместе с упаковкой.

## Что уже НЕ будет портироваться как есть

- Самообновление через подмену `.app` на лету (сработало для macOS,
  бинарник Windows на лету не подменяется, пока запущен) — заменяется на
  electron-updater, стандартное решение для Electron с автообновлением
  через GitHub Releases.
- Сканирование QR с камеры — уже убрано и из Swift-версии (не работало
  надёжно, неудобно на ноутбуке) — в порт не добавляем вообще.
