# ADB Shell Desktop

[![Desktop Build](https://github.com/andrei-s96s/adb-shell/actions/workflows/desktop-build.yml/badge.svg)](https://github.com/andrei-s96s/adb-shell/actions/workflows/desktop-build.yml)
![Платформы](https://img.shields.io/badge/Windows%20%7C%20macOS-Electron-4a4a55)
![Язык](https://img.shields.io/badge/TypeScript-Electron-3178c6)

Кроссплатформенный (**Windows и macOS**) порт [ADB Shell](../README.md) —
удобный интерфейс для повседневной работы с Android-устройствами через
`adb`, без десятка команд в терминале. Независимый Node/TypeScript/Electron
проект в этом же репозитории — не пересекается с Swift-кодом в `../Sources/`.
Со временем должен стать общей заменой Swift-версии, доступной не только на
Mac.

Бесплатно, без рекламы и без сбора данных.

## Скачать готовое приложение

Собранные пакеты публикуются автоматически на каждый релиз:
**[все релизы](https://github.com/andrei-s96s/adb-shell/releases)** — берите
самый свежий с тегом **`desktop-v*.*.*`** (в этом же репозитории отдельно
публикуется и Swift-версия для Mac, теги `v*.*.*` без префикса `desktop-`).
Например, прямая ссылка на версию 1.0.0:
[desktop-v1.0.0](https://github.com/andrei-s96s/adb-shell/releases/tag/desktop-v1.0.0).

- **Windows** — `ADB Shell Setup X.Y.Z.exe` (NSIS-инсталлятор). Windows
  SmartScreen предупредит про неизвестного издателя (сборка не подписана
  платным сертификатом) — «Дополнительно» → «Выполнить в любом случае».
  `adb.exe` и `aapt2.exe` вшиты прямо в установщик, отдельно ставить
  Android Platform Tools не нужно.
- **macOS** — `ADB Shell-X.Y.Z-arm64-mac.zip`. Не подписано платным Apple
  Developer ID, поэтому при первом запуске Gatekeeper покажет
  предупреждение — правый клик по `ADB Shell.app` → «Открыть» → «Открыть»
  в диалоге. `aapt2` вшит в сборку.

Приложение проверяет наличие новой версии при каждом запуске и показывает
баннер со ссылкой на страницу релиза — ничего не скачивает и не подменяет
само, новую версию нужно поставить вручную (см. [PLAN.md](PLAN.md) про то,
почему не полноценное автообновление).

## Возможности

### 📱 Устройства и подключение

- Список подключённых устройств: USB и сеть (`adb connect ip:port`)
- Сопряжение по коду (Android 11+, `adb pair`)
- Отключение сетевых устройств прямо из списка

### 📦 Приложения

- Список установленных приложений (пользовательские / системные) с поиском
- Детали приложения: версия, target SDK, даты установки/обновления, путь к
  APK, выдача/отзыв runtime-разрешений
- Установка (через нативный диалог выбора файла) / удаление, force stop,
  очистка данных, включение/отключение

### 🗂 Библиотека APK

Работает и без подключённого устройства:

- Локальная папка (по умолчанию `Documents/AdbShell/APK`, путь можно
  сменить), добавление файлов и скачивание по прямой ссылке
- Установка на выбранное устройство или сразу на все подключённые одним
  кликом, с отчётом об успехах/ошибках по каждому
- Проверка обновлений через официальный каталог **F-Droid** — бейдж с
  доступной версией, обновление ставится только по явному нажатию кнопки

### 🗄 Файлы устройства

Навигация по файловой системе устройства, создание папок, удаление.

### 💻 Shell и сеть

- Shell-раннер (`adb shell <команда>`)
- Wi-Fi отладка в один клик (`adb tcpip`) с показом IP:порта
- Проброс портов (`adb forward`/`adb reverse`) — список правил, добавление
  и удаление
- Просмотр всех системных свойств устройства (`adb shell getprop`) с
  поиском

### 📊 Мониторинг и диагностика

- Живые графики CPU и памяти, уровень и температура батареи — опрос
  каждые 2 секунды
- Список процессов (`ps -A`) с завершением (`kill`)
- Live Logcat: стриминг `adb logcat`, фильтр по тексту/тегу/уровню,
  подсветка по уровню, очистка буфера устройства

### ⚙️ Интерфейс

- Тема оформления: следует системной (светлая/тёмная)
- Проверка обновлений приложения на GitHub Releases (см. выше)

Планы и то, что сознательно ещё не перенесено из Swift-версии (макросы,
зеркалирование экрана scrcpy, снапшоты устройства, наборы приложений,
тегирование файлов) — см. **[PLAN.md](PLAN.md)**.

## Разработка

```bash
npm install
npm start
```

**Тесты** — только чистые функции парсинга (без Electron), через встроенный
тест-раннер Node, без Jest/Vitest:

```bash
npm test
```

**Сборка пакетов** (`electron-builder`):

```bash
npm run dist:mac   # ADB Shell-X.Y.Z-arm64-mac.zip
npm run dist:win   # ADB Shell Setup X.Y.Z.exe (NSIS)
```

## Структура проекта

```
desktop/
  src/
    main/
      main.ts            — точка входа Electron, окно, IPC-хендлеры,
                            глобальный перехват необработанных ошибок
      preload.ts          — contextBridge, единственный мост renderer → main
      updateChecker.ts    — проверка новых версий по GitHub Releases
      adb/
        AdbService.ts     — обёртка над CLI adb (порт ADBService.swift)
        parsers/          — чистые функции парсинга (порт Swift-парсеров,
                            те же тестовые кейсы)
        types/
      apkLibrary/
        ApkLibraryService.ts    — локальный каталог APK, aapt2, F-Droid
        FDroidUpdateChecker.ts
    renderer/
      index.html
      api.ts              — типизированная обёртка над window.adbApi
      state.ts             — текущее выбранное устройство + подписка
      tabs.ts               — переключение вкладок
      renderer.ts            — точка входа, список устройств, баннер обновлений
      screens/              — по одному модулю на вкладку
      styles/theme.css       — палитра портирована из Design/Theme.swift (CP.*)
    test/                 — юнит-тесты (node --test)
  scripts/
    fetch-windows-adb.js  — скачивает adb.exe + DLL для Windows-сборки
    fetch-aapt2.js        — скачивает aapt2 (mac/win) для чтения манифестов
    afterSign.js          — electron-builder hook: дошивает подпись macOS
                            после упаковки ресурсов (без этого Gatekeeper
                            жёстко отклоняет собранный .app)
  build/                  — иконки (icon.ico/icon.icns, из Resources/AppIcon.svg)
```

См. **[PLAN.md](PLAN.md)** — полная история решений и найденных багов по
каждой ревизии, с тем, как именно они были проверены (не только чтением
кода, а реальным запуском Electron и живой инспекцией через Chrome
DevTools Protocol).

## Почему Electron

Самый обкатанный в продакшене из рассмотренных вариантов (Tauri, Flutter,
Avalonia) — на нём держатся VS Code, Slack, Discord, Figma Desktop. Не самый
современный по архитектуре, зато с наибольшим запасом надёжности.

## Лицензии

`adb` и `aapt2` — части Android Platform Tools / Android Gradle Plugin от
Google, распространяются под Apache License 2.0; сборки кладут рядом
соответствующий `NOTICE`-файл. Лицензия на исходный код самого ADB Shell в
репозитории отдельно не указана (см. [лицензии в корневом README](../README.md#лицензии)).
